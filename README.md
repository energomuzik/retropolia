# RETROPOLIA — сборка и запуск на Windows

Онлайн-игра на 2–4 игроков: монополия, где вместо покупки клеток игроки проходят челленджи в эмуляторе NES/SEGA. В комплекте: редактор карт, редактор тайлов, редактор заданий, тестовый стенд эмулятора и синхронизация партий (PeerJS P2P + резервный tab-канал).

---

## 0. Как распаковать скачанный архив (.tar) на Windows

Кнопка «Скачать проект» отдаёт файл `project.tar`, а внутри него лежит файл `workspace` — это **второй, вложенный архив** с самим проектом. Распаковка — в два шага.

### Вариант А — командная строка (встроено в Windows 10/11, ничего ставить не надо)

Откройте PowerShell или CMD в папке «Загрузки» (или где лежит файл) и выполните:

```
tar -xf project.tar
```

Появится файл `workspace`. Это тоже архив — распакуйте его:

```
mkdir retropolia
tar -xf workspace -C retropolia
```

> `tar` сам понимает сжатие (gzip/xz), поэтому флаги `-z` не обязательны. Если вдруг `tar` не найден — берите вариант Б.

### Вариант Б — 7-Zip (бесплатный архиватор с интерфейсом)

1. Скачайте и установите [7-Zip](https://www.7-zip.org) (файл `7z…-x64.exe`).
2. Правый клик по `project.tar` → **7-Zip → Распаковать в "project\«**.
3. Внутри появится файл `workspace`. Правый клик по нему → **7-Zip → Открыть архив** (или «Распаковать в…»). 7-Zip распознаёт его как tar-архив.
4. Если 7-Zip не узнаёт формат — переименуйте `workspace` в `workspace.tar.gz` и повторите шаг 3.

### Вариант В — свежий Windows 11 (24H2 и новее)

Проводник умеет открывать `.tar` и `.tar.gz` как обычные папки: двойной клик по `project.tar`, зайдите внутрь, вытащите `workspace`, переименуйте в `workspace.tar.gz` и снова откройте двойным кликом.

### Проверка

В итоговой папке должны лежать: `package.json`, `index.html`, `README.md`, папки `src/` и `public/` (если есть). Дальше — по шагу 1 ниже.

## 1. Что нужно установить

1. **Node.js LTS (v20 или v22)** — скачать с [nodejs.org](https://nodejs.org), поставить «как обычно» (Next → Next). Он включает `npm`.
2. Проверить в PowerShell / CMD:

```
node -v
npm -v
```

Обе команды должны напечатать версии.

## 2. Установка зависимостей и запуск (режим разработки)

Откройте PowerShell или CMD в папке проекта (в Проводнике: зажать Shift + правый клик → «Открыть окно PowerShell здесь», либо `cd путь\к\retropolia`):

```
npm install
npm run dev
```

Откройте в браузере адрес из консоли (обычно **http://localhost:5173**). Готово — игра запущена.

> При первом запуске Windows может спросить разрешение для сетевого доступа Node — разрешите, если хотите играть по локальной сети.

## 3. Продакшен-сборка

```
npm run build
```

Готовый сайт появится в папке `dist/`. Чтобы открыть его локально:

```
npx serve dist
```

(или `npx http-server dist`) — адрес напечатается в консоли, например http://localhost:3000.

## 4. Как играть

| Режим | Как |
|---|---|
| **Тест 1 игрока** | «Создать игру» → выбрать карту → «Начать» без игроков. Подтверждения заданий автоматические. |
| **2 игрока, один ПК** | Открыть игру в **двух вкладках браузера**: первая — «Создать игру», вторая — «Подключиться» с кодом комнаты. Работает через встроенный tab-канал, мгновенно. |
| **Локальная сеть** | Запустить `npm run dev -- --host`, игроки заходят по `http://ВАШ_IP:5173` (IP виден командой `ipconfig`). |
| **Онлайн через интернет** | Каждый игрок открывает игру у себя (локально или на хостинге) и вводит один и тот же код комнаты. Знакомство идёт через публичный облачный брокер PeerJS — **проброс портов не нужен**. При очень строгих NAT-сетях P2P-канал может не пробиться — тогда используйте вариант с хостингом ниже. |
| **Публикация (по желанию)** | Загрузите содержимое `dist/` на Netlify / Vercel / GitHub Pages / Cloudflare Pages — бесплатно, HTTPS включён, онлайн-игра стабильнее. |

### 4.1. Онлайн с двух компьютеров — как это устроено и почему «вечно стучится»

Комнаты соединяются **по коду через интернет-ретранслятор (PeerJS)**, а не по адресу.
Поэтому `localhost` — это всегда «сам себя»: на втором компьютере вводить `localhost` бессмысленно,
он найдёт только свою же копию игры.

**Правильная схема (самая надёжная):**
1. На своём ПК: `npm run build` → появится папка `dist/`.
2. Откройте https://app.netlify.com/drop и перетащите `dist/` в окно браузера — получите ссылку вида `https://имя.netlify.app` (бесплатно, без регистрации аккаунта для разовой публикации).
3. **Оба** компьютера (или вы и друг) открывают эту ссылку.
4. Первый — «Создать игру» → код из 4 букв. Второй — «Подключиться» → ввести тот же код. Готово.

**Схема без публикации (локальная сеть + интернет для реле):**
1. На хосте: `npm run dev -- --host`. Vite напечатает `Network: http://192.168.X.X:5173`.
2. Второй компьютер открывает **именно этот** адрес (IP хоста), а не свой localhost.
3. Далее как обычно: создать игру → код → подключиться.

**Если «стучимся» висит:** теперь экран подключения показывает точную причину:
- **«Подключаемся к реле-серверу…»** — на этом ПК нет интернета или он закрыт (VPN, корпоративный файрвол, антивирус). Попробуйте мобильный хот-спот, отключите VPN.
- **«Комната не найдена»** — хост ещё не создал игру, закрыл вкладку, либо код введён с ошибкой. Версии игры на обоих ПК должны совпадать.
- **«Стучимся уже N с»** — реле на связи, но хост молчит: чаще всего второй компьютер открыл `localhost` (свою копию) вместо общего сайта.
- В лобби у хоста есть чип **«РЕЛЕ: НА СВЯЗИ / НЕТ СВЯЗИ»** — если «нет связи», игроки с других компьютеров не подключатся, даже если код верный.

Для онлайн-игры интернет нужен **обоим** компьютерам (через него идёт знакомство), даже если вы сидите в одной комнате.

### 4.2. Свой реле-сервер (если облако PeerJS «не знакомит» игроков)

Публичный брокер `0.peerjs.com` иногда перегружен: индикатор «РЕЛЕ: НА СВЯЗИ» горит, а игроки не
видят друг друга (пиров 0). Решение — **свой сервер знакомств**. Это работает как сервер TeamSpeak:
один публичный адрес (имя, а не ваш IP), его знают все игроки, свой IP раздавать никому не нужно.

> Glitch закрыл хостинг, поэтому используем **Render** или **Koyeb** (бесплатно, через GitHub).
> В корне проекта уже лежит готовый сервер — папка **`server/`**, полная инструкция в `server/README.md`.

**Вариант А — интернет-сервер на Render (рекомендуется, бесплатно):**

1. Создайте бесплатный репозиторий на github.com и загрузите туда `server/server.js` и `server/package.json`.
2. https://render.com → войти через GitHub → «New» → «Web Service» → выбрать репозиторий.
3. Build: `npm install`, Start: `npm start`, Instance Type: **Free** → «Create Web Service».
4. Адрес — `https://имя.onrender.com`. Проверка: `https://имя.onrender.com/health` → `{"ok":true,...}`.
5. На **всех** компьютерах: «Опции» → «Свой реле-сервер» → вписать `имя.onrender.com`.

(Альтернатива — **Koyeb**, тоже бесплатно из GitHub: `server/README.md`, Вариант 2.)

**Вариант Б — свой компьютер + Cloudflare Tunnel (публичный адрес без раздачи IP):**

1. Локально: `cd server && npm install && npm start` (порт 9000).
2. `cloudflared tunnel --url http://localhost:9000` → получите адрес `https://слово-слово.trycloudflare.com`.
3. На всех компьютерах: «Опции» → «Свой реле-сервер» → вписать этот адрес.

**Вариант В — локально, без интернета (одна сеть):**

1. На любом компьютере сети: `cd server && npm install && npm start`.
2. Его IP: `ipconfig` → «IPv4-адрес» (например `192.168.1.10`).
3. На всех компьютерах: «Опции» → «Свой реле-сервер» → `192.168.1.10:9000`.

После этого знакомство идёт через ваш сервер, а сама игра — напрямую P2P между игроками.

### 4.3. Как проверять обновлённые версии (Netlify-сайт истекает)

Сайт на Netlify Drop живёт ограниченное время и даёт **новый адрес при каждой загрузке**. Чтобы не гадать:

- **Быстро (разовая проверка):** `npm run build` → перетащите свежую папку `dist/` на
  https://app.netlify.com/drop → получите новую ссылку → откройте её на обоих компьютерах.
- **Постоянно (рекомендуется):** зарегистрируйте бесплатный аккаунт на netlify.com
  («Claim this site» → или Add new site → Deploy manually) и закрепите сайт. Ссылка станет постоянной,
  а новые сборки перетаскиваются в раздел **Deploys** — адрес не меняется, и у игроков не «слетают» настройки.

Помните: карты и ромы хранятся **в браузере каждого игрока** (IndexedDB), а не на сервере.
Если адрес сайта всё же сменился — перенесите библиотеку: «Опции → Данные → Экспорт / Импорт».

## 5. Ромы и сохранения

- Раздел **«Запуск эмулятора»** → «Загрузить ром»:
  - `.nes` — NES, встроенное ядро jsnes, работает офлайн;
  - `.md/.gen/.bin` (Mega Drive), `.sms` (Master System), `.gg` (Game Gear) — SEGA, ядро Genesis Plus GX подгружается **один раз** с CDN emulatorjs.org и кэшируется браузером (нужен интернет при первом запуске SEGA-рома).
- **Управление:** клавиатура (раскладка настраивается в Опциях → «Эмулятор») и геймпады — PS5 DualSense, Xbox, PC-джойстики (NES: геймпад 1 → игрок 1, геймпад 2 → игрок 2; в SEGA — встроенная поддержка ядром).

### Про «подгрузку» SEGA-ядра

NES-ядро (jsnes) вшито в приложение и стартует мгновенно. SEGA-ядро Genesis Plus GX — это
скомпилированный WebAssembly (~10–20 МБ), который физически нельзя положить в npm-пакет;
при **первом** запуске SEGA-рома он один раз скачивается с CDN emulatorjs.org и остаётся
в кэше браузера. Повторных загрузок нет: и в «Запуске эмулятора», и во время партии ядро
берётся из кэша, а загрузка сохранений вообще не перезапускает эмулятор (состояние грузится
прямо в работающее ядро, без перезагрузки). Для SEGA нужен интернет только при самом первом
запуске на конкретной машине/браузере.

- Играете (NES или SEGA), доходите до нужного места → **«Сохранить состояние»** → слот. Неверные слоты удаляются кнопкой корзины. Сохранения SEGA работают как у NES: выбираются в редакторе заданий (или «без сохранения» — старт с начала рома).
- В **редакторе заданий** к ячейке привязывается пара «ром + слот», плюс название, описание и картинка.
- «Папки шаблонов» из замысла реализованы через саму библиотеку: ромы со слотами 1, 2, 3… — это и есть уровни-шаблоны, которые игроки выбирают прямо во время партии (кнопка «Новое задание» после захвата ячейки).
- **Важно:** используйте только ромы, права на которые у вас есть. Игра ничего не распространяет — файлы загружаете вы сами.

## 6. Где хранятся данные

Всё (тайлы, карты, ромы, сохранения, сессии, фишки) лежит в **IndexedDB браузера** на вашей машине —
не на сервере (версия БД v2 — при обновлении игры старые карты и ромы сохраняются автоматически):

- у каждого браузера — своя библиотека;
- **важно:** хранилище привязано к адресу сайта. `http://localhost:5173` и ваш сайт на Netlify — это
  *разные* библиотеки, поэтому карты, созданные на localhost, не видны на опубликованном сайте (и наоборот);
- карта при создании онлайн-комнаты **передаётся всем игрокам автоматически** (версия протокола должна совпадать);
- полная очистка — «Опции» → «Очистить библиотеку».

### Перенос библиотеки (экспорт / импорт)

Чтобы не создавать карты заново при переезде на новый сайт или на другой компьютер:

1. «Опции» → «Данные» → **«Экспорт библиотеки»** — скачается один JSON-файл со всеми картами,
   тайлами, ромами, сохранениями и фишками.
2. На новом месте (другой сайт / другой компьютер) → «Опции» → «Данные» → **«Импорт библиотеки»** →
   выберите этот файл. Данные сольются с текущей библиотекой.

## 7. Если что-то не так

- **«Невозможно загрузить файл …npm.ps1, так как выполнение сценариев отключено»** — это политика безопасности PowerShell, не ошибка проекта. Выберите **одно** из трёх:
  1. *(рекомендуется)* Разрешить скрипты для вашего пользователя — выполните один раз в PowerShell:
     ```
     Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
     ```
     на вопрос ответьте `Y`. После этого `npm` работает всегда.
  2. Пользоваться **обычным CMD** (cmd.exe) вместо PowerShell — там npm запускается без ограничений: Пуск → «cmd» → `cd путь\к\retropolia` → `npm install`.
  3. В том же PowerShell вызывать npm напрямую как `npm.cmd`:
     ```
     npm.cmd install
     npm.cmd run dev
     ```
- `npm install` падает — обновите Node до LTS и повторите; при проблемах с сетью: `npm config set registry https://registry.npmmirror.com`.
- Порт занят — `npm run dev -- --port 5180`.
- Игроки не видят друг друга онлайн — сверьте, что версии игры одинаковые, код введён верно; для теста используйте две вкладки одного браузера (tab-канал работает всегда).
- Нет звука/управления в эмуляторе — кликните один раз по странице (браузеры требуют первое действие пользователя для аудио).
